    ℹ️ 이 태그, 나중에 어떻게 가져다 쓰나요? (URL 사용법)

    동작 방식 — 서버가 2초마다 이 폴더의 모든 태그를 PLC에서 미리 읽어 메모리에 들고 있습니다. 아래 URL을 호출하면 PLC와 통신하지 않고 메모리에 있는 최신값을 즉시 돌려줍니다.

    ① 폴더 전체 값 한번에 조회

    GET http://<서버IP>:5050/api/foldertag/values?folderId=4
    {
  "success": true,
  "folderId": 4,
  "lastPollAt": "2026-09-04T05:33:07Z",
  "tags": [
    { "name": "name_1", "address": "D100", "value": 50531 }
  ]
}

    ② 태그 이름으로 값 하나만 조회 (같은 이름이 여러 폴더에 있으면 배열로 반환)

    GET http://<서버IP>:5050/api/foldertag/value/by-name?name=태그이름

    ③ PLC 주소로 직접 조회 (태그로 등록 안 돼 있어도 동작)

    GET http://<서버IP>:5050/api/foldertag/value/by-address?plcId=MST_MITSUBISHI&address=D100

    ④ 값 쓰기 — ⚠️ 실제 설비 PLC에 값을 내보내는 되돌릴 수 없는 동작입니다. 신중하게 사용하세요.

    GET http://<서버IP>:5050/api/foldertag/write/by-name?name=태그이름&value=123

    위 4개는 이미 서버에 구현되어 있어 지금 바로 호출 가능합니다. 이 관리 화면은 "값"이 아니라 태그 정의(이름/주소/PLC)만 관리합니다.

      ℹ️ 온도 태그를 저장하면 무슨 일이 생기나요? (tb_temp_snapshot 설명)

      동작 방식 — 온도 태그 1개 = tb_temp_snapshot 테이블의 컬럼 1개입니다. 태그를 저장하는 즉시 col_name 이름으로 컬럼이 생성되고(이미 있으면 건너뜀), 이후 서버가 30초마다 이 태그가 속한 PLC에서 실제 값을 읽어 scale 보정식을 적용한 뒤 스냅샷 한 행으로 저장합니다. 즉 한 "행"에 그 시각 모든 온도 태그의 값이 컬럼별로 나란히 쌓입니다.

      필드의미
      태그 이름화면/보고서에 표시할 이름 (예: "No.1 Zone")
      주소PLC 레지스터 주소 (예: D100) — 항상 워드(D) 읽기로 동작
      컬럼명(col_name)tb_temp_snapshot의 실제 컬럼명. 영문/숫자/밑줄만 가능, 저장 시 즉시 컬럼 생성
      트렌드명그래프 범례 등에 쓰는 짧은 표시 이름 (예: "1존")
      스케일보정식. 맨 앞 1글자가 연산자(+,-,*,/), 나머지가 숫자 (예: "+50", "*0.01"). 비워두면 PLC 원시값 그대로 저장
      설비(equip_id)여러 온도 태그를 같은 설비 단위로 묶는 자유 입력 값 (예: "BCF1")

      예시 — 태그 이름 "No.1 Zone", 주소 D100, 스케일 "+50" 저장 → PLC에서 읽은 원시값이 120이면 → 120+50 = 170.0이 tb_temp_snapshot의 해당 컬럼에 저장됨.

      현재 저장된 실제 컬럼 목록 (tb_temp_snapshot, 실시간 조회)

      불러오는 중...

      ⚠️ 컬럼명을 나중에 바꾸면 예전 데이터는 예전 컬럼에 그대로 남고 새 컬럼이 새로 생깁니다(자동 이관 안 함). 태그를 삭제해도 기존 컬럼과 과거 데이터는 보존됩니다(추세 이력 보호).
      현재 추세 값 조회 전용 API는 없습니다 — DB(tb_temp_snapshot)를 직접 SELECT해서 확인합니다.

        ℹ️ 알람 태그는 어떻게 동작하나요?

        동작 방식 — 서버가 2초마다 이 태그의 PLC 주소를 읽어, 값이 OFF→ON 또는 ON→OFF로 전환되는 순간에만 tb_alarm_history 테이블에 이력을 1건 기록합니다(값이 그대로 유지되는 동안은 기록하지 않음). 레벨은 알람 심각도를 화면에서 구분하기 위한 숫자입니다(값이 클수록 심각하다는 식의 규칙은 이 화면을 쓰는 쪽에서 정하면 됩니다).

        ⚠️ 현재 알람의 실시간 상태나 이력을 바로 조회하는 URL API는 아직 없습니다 — 필요하시면 tb_alarm_history 테이블을 직접 조회하거나, 별도로 조회 API 추가를 요청해주세요. 이 화면은 태그 정의(이름/주소/메시지)만 관리합니다.
